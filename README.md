## Ответы на вопросы

1. Чем статическая типизация Dart отличается от Python? Какое практическое
преимущество она даёт?

В Dart тип проверяется ещё при компиляции. Если я напишу int x = "привет"; —
программа просто не соберётся. В Python такое прокатит, и ошибка вылезет только
когда до этой строки дойдёт выполнение.

Преимущество: ошибки ловятся раньше, ещё до запуска. Плюс код понятнее — по
сигнатуре функции сразу видно, что она принимает и что возвращает. И IDE
подсказывает точнее. В общем, меньше багов и больше удобства.

2. Что означает String?? Чем отличается от String?

String? — это тип, который может быть либо строкой, либо null. Обычный
String — гарантированно строка, без null.

 
String a = 'hello';   // ок
String b = null;      // ошибка
String? c = null;     // ок


Удобно тем, что компилятор заставляет проверить на null, прежде чем что-то
делать со значением:

 
String? city = null;
if (city != null) {
  print(city.toUpperCase());
}


Без ? проверка не нужна — там null быть не может.

3. Зачем в Dart final, если в Python можно просто договориться не менять
переменную?

Потому что final — это гарантия компилятора, а «договориться» — это просто
правило в голове. В Python случайно переприсвоил переменную — никто не заметит.
В Dart компилятор не даст:

 
final String lang = 'dart';
lang = 'python'; // ошибка компиляции


Плюсы: случайно не перезапишешь, код понятнее (видно, что значение неизменяемо),
и компилятор может лучше оптимизировать. Ещё есть const — это final, но для
значений, известных заранее, на этапе компиляции.

4. Чем именованный параметр {required String name} отличается от
позиционного? Приведите пример вызова.

Позиционный — передаётся по порядку:

 
void greet(String name, int age) { ... }
greet('vlad', 24); // важен порядок


Именованный — в фигурных скобках, передаётся по имени, порядок не важен:

 
void printStatus({required String name, required List<int> grades}) { ... }

printStatus(name: 'vlad', grades: [5, 5, 5]);


Отличия:
- у позиционных порядок важен, у именованных — нет;
- при вызове сразу видно, что куда передаётся — читается легче;
- required делает параметр обязательным, без него он необязательный (и тогда
  нужно значение по умолчанию или nullable-тип);
- когда параметров много, именованные вызовы гораздо понятнее.

Пример с необязательными:

void Pet({required String name, String species = 'cot', int age = 0}) { ... }

Pet(name: 'leha');                       // species = 'cot', age = 0
Pet(name: 'barsik', species: 'psina');   // age = 0
Pet(name: 'murka', age: 3, species: 'cat'); // порядок не важен
